# THE LAST COMMAND — динамическая машина

Реализовано в существующих Java-комнатах и браузерном Three.js runtime. Исходная Java/libGDX сцена и три диагностических сценария сохранены. Основной браузерный режим по умолчанию — campaign.

## Запуск на Mac

Из `/Users/erni/Documents/FinalAnswer`:

```sh
PORT=18095 ./THE_LAST_COMMAND_DEV
```

Откроется `http://localhost:18095/last-command-3d/?autostart=1`. После загрузки пустой машины нажмите START. Скрипт собирает frontend, запускает watcher и один Java-сервер на `0.0.0.0`. Ctrl+C завершает оба процесса. Нужны Java 21, Node/npm, Python 3. Если выбранный порт занят, задайте другой PORT; чужие процессы скрипт не останавливает.

Для телефона в той же Wi-Fi-сети откройте ссылку «Подключить телефон» в игре, укажите уникальное имя и нажмите «Подключиться к DEV». Список адресов также печатается в терминале; приоритет — физические интерфейсы en0/en*. На телефоне можно создать отдельную машину через «Подключить машину».

## Правила и взаимодействие

- Первый игрок с 20 верными ответами побеждает. Сервер хранит счёт каждого участника; CRT показывает собственный счёт. Задание и механизмы общие для комнаты. Очко получает отправитель верного подтверждения/завершающего действия. Камера локальна.
- Ошибки не снимают очков и не заканчивают игру. Через сообщение WRONG COMMAND начинается новая задача. Лимита общего времени нет.
- Ввод кода, животное, символ, цвет, рычаг и регулятор подтверждаются большой красной кнопкой. Люк и цветные кнопки срабатывают непосредственно.
- Положения рычага, регулятора и цвета можно менять без штрафов до подтверждения.
- Запоминание числа, животного, символа, цвета и последовательности ламп хранится на сервере; вопрос появляется после других задач. Сам показ памяти очка не даёт. Числа и карточки исчезают через 4,5 с; исходная подсказка после показа не отображается на CRT.
- Перетаскивание вращает камеру; короткий клик/касание работает по реальной 3D-геометрии. «К механизму» показывает нужную сторону. Карточки находятся сзади; CRT остаётся спереди.
- После результата можно начать новую партию. Диагностические сценарии mechanisms / memory / inspection доступны отдельно в селекторе.

## Архитектура

`LastCommandGame` — серверный Task Manager: seeded перемешиваемый набор типов, процедурные параметры, отложенная память, условия проверки, переходы и победитель. Решения находятся в серверном Task; клиент получает только экран, механизмы, сроки переходов и данные текущей световой демонстрации. `gameSeed`, `taskSeed`, `taskId` доступны для воспроизведения. Неоднозначные одновременно ожидающие подсказки памяти исключены.

`LastCommandSession` сохраняет существующий протокол и защиту комнат: действия последовательны, повторные requestId не засчитываются, скрытые узлы и ввод во время переходов/демонстрации памяти блокируются сервером. Обычный START_LAST_COMMAND запускает campaign. Локальное подключение подготавливает READY, START начинает раунд.

`Mechanisms` управляет HIDDEN / APPEARING / ACTIVE / DISAPPEARING / DISABLED. Анимация развёртывания/свёртывания занимает 320 мс, использует pivot экземпляра и наружное крепление. Собственное движение кнопки, рычага, дверцы и регулятора независимо. Все неиспользуемые группы невидимы; они исключены из raycast и рендера. Новый набор ждёт ухода предыдущего. Ввод активируется после серверного readyAt.

Основная информация рисуется CanvasTexture на штатном CRT, с прогрессом, иллюстрациями памяти, инструкциями, выбранными положениями и обратной связью. Текстура обновляется по изменению содержимого, GLB не перезагружается. Узкая боковая панель содержит только комнату, настройки и справку; дубли заданий в campaign скрыты.

## Модели и оптимизация

Использованы `box_final`, `hole_final`, `button`, `adjuster`, `light`, `level_handler`, `lever`, `secret_hole`, `door`, `code_display`, `animal_panel`. Одна модель button переиспользуется для большой и четырёх цветных кнопок; одна металлическая animal_panel служит животным и символам с разными текстурами. `panel_lamps.png` и `hole1.png` используются в поверхностях соответствующих узлов.

Оригиналы не изменялись. Подготовлены четыре копии animal_panel: mobile ~756 КиБ, low ~884 КиБ, medium/high ~1,7 МиБ вместо исходных 46,7 МиБ. SHA и параметры записаны в `assets/models/last_command/cards-optimization.json`. Повторная подготовка:

```sh
GLTFPACK=/path/to/gltfpack python3 tools/assets/prepare_last_command_cards.py '/path/to/source/models'
```

Остальные ранее оптимизированные модели сохранены. Во время партии — 11 загрузок GLB, без дополнительных загрузок при смене заданий. Качество LOW / MEDIUM / HIGH и восстановление LOW сохранены; LOW ограничен 30 FPS, остальные — 60 FPS. Скрытие уменьшает draw calls, но предзагруженные ресурсы занимают память до выхода из сцены.

## Проверки 27 октября 2026

- `./gradlew :server:test --console=plain`: 171 тест, 0 ошибок. Включая комнаты и другие мини-игры, шесть новых тестов campaign, 120 полных seeded партий и все пять видов памяти.
- `npm run build --prefix web3d`: успешная сборка.
- `check_last_command_campaign.cjs`: два реальных HTTP/WebSocket-клиента Chromium, все 10 типов генератора, 20 правильных ответов + намеренная ошибка, три отложенных вопроса, реальные клики по карточкам, синхронные результаты, перезапуск, 11 GLB без перезагрузок, 0 ошибок JS.
- `check_last_command_3d_controls.cjs`: касания настоящих cap/code-arrow, восстановление истёкшей сессии, ошибки протокола и восстановление ввода, LOW → MEDIUM → HIGH → LOW, восстановление количества GPU-ресурсов, 0 ошибок шейдеров.
- `check_last_command_mobile_smoke.cjs`: Chromium mobile emulation, 390×844, touch, отсутствие горизонтального переполнения, скриншот. Это **не физический телефон**.
- Короткий benchmark на Mac Apple M4, Chromium/ANGLE Metal, вращение 5 с/профиль, диагностический набор со всеми механизмами: LOW ~29,6 FPS, MEDIUM ~60 FPS, HIGH ~60 FPS. Это не длительный тепловой тест и не замер слабого смартфона; GPU time и фактическая VRAM не измерялись.

JSON-отчёты и скриншоты: `generated/last-command-campaign/`. Скрипты используют `PLAYWRIGHT_MODULE`, `CHROME_PATH`, `LC_URL`; настройки можно передать для установленного локального Playwright/Chromium. Полный браузерный прогон занимает несколько минут и взаимодействует с настоящим Java-сервером.

Физические Android/iPhone не тестировались. Проверка Safari на iPhone, реальных touch-жестов, длительного нагрева и FPS на слабом телефоне остаётся необходимой; обещание стабильных 30 FPS на таких устройствах пока не подтверждено.
