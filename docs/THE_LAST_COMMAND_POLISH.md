# THE LAST COMMAND — улучшение сцены, управления, заданий и нагрузки

25 октября 2026. Точка отката перед этой итерацией: `287299a`. Запуск прежний: `./THE_LAST_COMMAND_DEV`, http://localhost:8080/last-command-3d/?autostart=1.

## Внешний вид

Переработаны игровой интерфейс, карточка задания, прогресс, таймер, список восстановленных узлов и результат. Технические метрики спрятаны в раскрываемый раздел; названия в обычном интерфейсе переведены на русский. Загрузка показывает фактическое число готовых GLB, а не выдуманный процент.

Добавлены промышленный пол, мягкое контактное затемнение одной малой текстурой, затухающий в темноте фон и перенастроенный нейтральный свет. Это не дополнительные полноэкранные постэффекты. Кэш теней HIGH и остановка лишних кадров в idle сохранены.

Панели животных/символов теперь используют собственные рисованные силуэты, гравированные плитки, крепёж, потёртый металл и выбранное состояние. Системных эмодзи больше нет. Сигнальные линзы получили стеклянные градиенты и отражения. Панели — по-прежнему лёгкие закреплённые 2D-поверхности, не выдуманные GLB.

## Управление и удобство

- Кнопка «К механизму» плавно переводит камеру к узлу текущего задания; «Спереди», «Сзади» и сброс камеры доступны поверх сцены.
- Переход идёт по дуге, а не через корпус. Ограничены расстояние до компьютера и проход под пол. Учитывается prefers-reduced-motion.
- Короткий tap даёт полный механический ход; локальная анимация начинается без ожидания сетевого ответа. Сервер остаётся источником состояния, отклонение восстанавливает последнее принятое состояние.
- Быстрые нажатия разных cap не теряются из-за таймера предыдущего нажатия. При RATE_LIMITED отпускание повторяется до подтверждения; новые PRESS отменяют устаревший retry, серверный limiter не ослаблен.
- Для touch увеличены непересекающиеся области стрелок внутри панели кода и минимальный размер HTML-кнопок. Требование выбирать именно красную поверхность cap сохранено.
- Hover picking ограничен по частоте, сами нажатия не задерживаются. Подсказки показывают понятные имена механизмов, а не enum ID.
- Добавлены отключаемые лёгкие механические звуки и сигналы правильного/неправильного ответа. WebAudio включается после жеста; файлов/фоновую аудиопетлю не загружает. Шумовой тембр не влияет на игровой seed.
- «Новый раунд» по умолчанию повторяет текущий сценарий. Гость обычной комнаты видит ограничения ведущего; в лобби показывается ожидание игроков.

## Тестовые задания

Прежние mechanisms и memory сохранены. В memory доступны два серверных повтора последовательности; они не продлевают deadline. Повтор синхронизирован через signalStartedAt. Надпись на CRT переходит от показа к повторению по серверному времени, не ожидая следующего heartbeat.

Добавлен явно тестовый **«Аварийный протокол» / inspection**: семь целевых состояний можно восстановить в своём порядке; список отмечает текущую готовность. Правильный набор нужно подтвердить большой кнопкой. Неверное подтверждение расходует попытку. Это не утверждённый дизайн будущих двадцати головоломок.

Правила и проверка остаются в Java LastCommandTestRound. Клиент только отображает цели, время и принятую сервером готовность. Прежний `/ws` и правила обычных комнат сохранены.

## Реальная оптимизация мобильной геометрии

Создан отдельный browser-only профиль `assets/models/last_command/mobile/`. Старые low/medium/high и оригиналы не менялись. Он используется браузерным LOW и безопасным стартом автоподбора. Ручные MEDIUM/HIGH сохраняют прежние более подробные ресурсы.

Скрипт: `tools/assets/prepare_last_command_mobile.py`, gltfpack 1.3, отключённая quantization, сохранение именованных nodes/materials, locked borders, относительное ограничение ошибки 0,002. Геометрия упрощается, но модели не центрируются заново и pivots не переопределяются. Новых loader extensions нет.

| Ресурсы десяти источников | Прежний low | Browser mobile |
|---|---:|---:|
| Уникальные треугольники | 633 068 | 270 938 |
| Размер GLB | 32,56 MiB | 23,94 MiB |
| Буферы геометрии в браузере, расчёт | 18,51 MiB | 9,89 MiB |

Все 30 встроенных PBR-изображений mobile побайтово совпадают с изображениями исходного low. SHA-256 оригиналов и 30 нативных profile GLB совпадают с прежним optimization.json. Карты не пережимались: выигрыш по текстурной памяти не заявляется.

Ненужные canvas-перерисовки при одинаковом состоянии устранены. Render-label GPU query кэшируется. Убрана лишняя callback-аллокация проверки анимации в каждом кадре.

### Сравнение в одинаковых условиях

Chromium headless, ANGLE Metal / Apple M4, LOW, viewport 1400×1000, backbuffer 1082×928, DPR1, seed20261025, одинаковая новая сцена/освещение/UI, один пятисекундный путь камеры. `?baseline=1` включает старую low-геометрию только для сравнения. В обоих случаях лимит 30 FPS.

| Метрика | Baseline | Mobile |
|---|---:|---:|
| FPS | 30,00 | 30,00 |
| Средние draw calls | 23,02 | 19,02 |
| Средние rendered triangles | 654 830 | 286 764 |
| CPU render submission, среднее | 1,49 мс | 1,38 мс |
| Загрузка источников | 0,75 с | 0,55 с |

Это одна короткая пара прогонов. Разницу CPU/load нельзя считать стабильным ускорением; детерминированно уменьшены геометрия, буферы и число вызовов. VRAM, GPU time, температура и длительный thermal throttling не измерены. Стабильные 30 FPS слабого Android не обещаются.

Сырые результаты: `generated/last-command-polish/{baseline,mobile}-performance.json`. Старый внешний вид и предыдущий benchmark сохранены в checkpoint/предыдущих отчётах; сравнение выше изолирует именно смену геометрии при одинаковом новом оформлении.

## Проверки

- Server build, core/shared verification и desktop compile; npm browser bundle.
- 161 серверный JUnit тест, 0 failures/errors: прежние плюс inspection confirmation и ограниченный replay без продления deadline.
- Реальные Chromium/HTTP/WS: оба прежних сценария, общая DEV-панель, host+2 guests, reconnect, ray picking, отсутствие PRESS при orbit, touch cap/code, win/loss/restart, rejected action recovery.
- LOW→MEDIUM→HIGH→LOW возвращает исходные resource counts; shader errors не обнаружены.
- Новый inspection доведён до WON, неверное подтверждение проверено; семь целей показаны. Replay выполнен через сервер, deadline не изменён, memory после повтора доведён до WON.
- Стресс-проверка через 80 SYNC: RATE_LIMITED сработал, отпускание автоматически восстановлено; две разные 3D-кнопки нажаты подряд без потери события.
- Проверен безопасный переход камеры к узлу. Скриншоты front/rear/mobile осмотрены; первая слишком тёмная версия панелей исправлена ради читаемости.
- Оригиналы/нативные варианты сохранены, PBR-карты mobile идентичны исходным. Front/rear и ray-тесты прошли; идеальная геометрия со всех ракурсов не утверждается.

Дополнительные автотесты: `tools/checks/check_last_command_polish.cjs`, `check_last_command_rate_recovery.cjs`. JSON и снимки: `generated/last-command-polish/`.

## Что остаётся

Настоящие Android/iPhone/Safari и длительный нагрев требуют физического теста. Мобильная геометрия стала существенно легче, но по-прежнему не сертифицирована для слабых GPU. Качество корпуса ограничено исходными запечёнными текстурами; художественная переработка исходных карт в этот этап не входила. Публичный deployment и финальные двадцать задач не реализовывались.

Файлы этой итерации: web3d runtime/view/assets/network/audio/stage, модуль last-command (machine/labels/panel-art), HTML/CSS, LastCommandTestRound/Session, dev GLB allowlist, mobile-optimization.json и builder, серверные tests, браузерные polish/rate-recovery checks и benchmark. Нативные игровые исходники и исходные GLB не изменялись.
