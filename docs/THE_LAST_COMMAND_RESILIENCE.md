# THE LAST COMMAND — удобство и восстановление сцены

26 октября 2026. Запуск прежний: `./THE_LAST_COMMAND_DEV`.

## Что изменилось

- Пункты «Аварийного протокола» стали кнопками: можно перейти камерой прямо к соответствующему узлу. Работают клавиатурный фокус и понятные aria-label.
- Ссылка подключения телефона теперь кликабельна; добавлена кнопка копирования с резервным способом для браузеров без Clipboard API.
- Звук и выбранное качество сохраняются на устройстве. Выключенный звук не создаёт AudioContext при каждом первом клике; выключение приостанавливает существующий контекст.
- Недоступное/повреждённое хранилище настроек не блокирует игру. При запрещённом sessionStorage текущая авторизация работает в памяти, но не переживает reload.
- При ошибке HIGH/MEDIUM клиент освобождает неудавшуюся загрузку и восстанавливает LOW. При ошибке LOW доступен явный повтор. Последнее состояние сервера и камера сохраняются, старое сообщение об ошибке исчезает после успешного повтора.
- Качество и автоподбор блокируются на время загрузки/калибровки. Повторные клики создания комнаты не запускают несколько одновременных запросов.
- Автоподбор после ручного HIGH/MEDIUM сначала освобождает тяжёлые модели и загружает mobile/LOW, затем измеряет рендер с базовым разрешением. Ранее можно было получить низкий render profile, сохранив тяжёлые ресурсы в памяти.
- При разрыве соединения появляется явный статус, игровые действия не отправляются, локальные нажатия отпускаются. После reconnect восстанавливаются серверные состояния; кнопки дополнительного управления показывают held/selected/locked через disabled и aria-pressed.
- Одинаковый сетевой snapshot больше не запускает GPU-кадры и карту теней. Изменение held/locked/состояний/условий по-прежнему обновляет сцену. Отдельно сохраняется временная анимация сигналов.
- При возвращении в окно/вкладку клиент запрашивает SYNC. Таймеры повторных отправок и heartbeat используют performance.now; ожидаемые игровые фазы в тестах отсчитываются от серверного времени. Это важно после сна Mac или при несовпадении часов устройств.
- Освобождение Machine сделано идемпотентным, чтобы повторный cleanup не обращался к уже освобождённым ресурсам.

## Проверки

Новый `tools/checks/check_last_command_resilience.cjs` запускает настоящий Chromium и существующий Java-сервер:

1. Настройки звука/LOW и sessionId переживают reload.
2. Клик по цели переводит камеру к задней панели.
3. Clipboard содержит настоящую ссылку комнаты.
4. Автоподбор после MEDIUM возвращает mobile-ресурсы.
5. Принудительный HTTP 503 для HIGH → рабочий LOW, прежняя камера и сессия.
6. Принудительный HTTP 503 для LOW → кнопка повтора → рабочая сцена.
7. Принудительное закрытие WebSocket → блокировка действий → reconnect той же сессии.
8. aria-pressed соответствует принятому сервером цвету индикатора.
9. Одинаковый SYNC после idle даёт 0 новых render кадров в тестовом интервале.
10. При искусственном запрете Storage API игра всё равно запускается.
11. После искусственного смещения клиентского timeOffset возврат фокуса восстанавливает серверное время.

Регрессии: `check_last_command_3d.cjs`, `check_last_command_3d_controls.cjs`, `check_last_command_rate_recovery.cjs` — пройдены, включая два сценария до победы, host+2 guests, touch cap/code, restart/reconnect, смену LOW/MEDIUM/HIGH и восстановление отпускания после rate limit.

Gradle server build, core/shared verification, desktop compile и npm browser bundle — успешно. Существующий набор: 161 серверный тест, 0 failures/errors. Новые проверки этого этапа браузерные; число Java-тестов не увеличивалось.

Один ранний прогон memory остановился из-за неверного предположения автотеста о совпадении Date.now с серверным монотонным временем после сна Mac. Ожидания переведены на serverTime/timeOffset, после чего регрессии прошли. Правила/таймеры игры не подменялись клиентскими.

Результат и снимок: `generated/last-command-resilience/report.json`, `scene.png`. Это проверки Chromium на Mac и эмуляции, не испытания физических Android/iPhone/Safari. Новое ускорение FPS или снижение температуры не заявляется; проверено устранение лишних кадров при одинаковом snapshot.
