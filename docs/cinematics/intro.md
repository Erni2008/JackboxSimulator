# Вступительная сцена FINAL ANSWER

Сцена встроена в существующий подвал и переход START GAME → первый вопрос.
Новых фонов, моделей, движка или сетевой комнаты нет. Рендер использует тот же
`CageLobbyScreen`, восемь `HangingCage`, персонажей и назначения игроков.

## Текущая редакция сценария

Начальный сценарий сохранён с последующими правками пользователя:

- «О-о-о… Ну наконец-то!» → выбранная проба «О, ну наконец-то!».
- «Да-да!» → «Да!» по просьбе убрать растянутые повторы через дефис.
- Последнее «Добро пожаловать в… FINAL ANSWER!» удалено.
- Последующая правка: «Ах, да!» заменено спокойным отдельным «Точно.».
  «Где же мои манеры?» — отдельный клип; пользователь выбрал третий дубль
  (seed 3, temperature 0.8). Настройки сохранены в generation строки для воспроизводимости.
- «Итак, мои драгоценные экспонаты!» пересоздано с ясным завершением;
  до «Первый вопрос!» сохранена пауза 1,2 секунды после фактического завершения.
  Изменённые клипы имеют 0,18 секунды технического запаса после речи до обработки.
- Паузы перераспределены перед обещанием свободы, «А остальные…» и угрозой испытаний.
- Текст субтитров отделён от синтеза: исправлены запятые в «Ах, да!»,
  «И, поверьте, …», «Но, знаете, …». Изменение пунктуации субтитров не запускает TTS.

Конфигурация: `shared/src/main/resources/cinematics/intro_ru.json`.
Измеренный отчёт: `assets/cinematics/intro_timing.json` — все строки, файлы,
старты, длительности, локальные превышения бюджета и отсутствующее аудио.

Целевая длительность — 74 секунды, измеренная последовательность — **74,3 секунды**,
максимальная — 80. Сумма клипов после обработки составляет около 54,3 секунды.
Локальные задержки не перекрывают реплики: следующие сцены сдвигаются, затем
возвращаются к целевому расписанию, если есть запас. Звук не ускоряется и не обрезается.
Фактическое завершение также ждёт окончания последней реплики и короткого fade-out.

## Реализация

`IntroDefinition` — общий неизменяемый сценарий без libGDX, `IntroTimeline` —
расписание по измеренным длительностям, `IntroSequenceController` — чистая
машина WAITING/PLAYING/EXITING/PAUSED/COMPLETED/SKIPPED/TIMING_CONFLICT.
`BasementIntro` содержит только 2D-представление, субтитры и ввод.
Эту границу можно заменить будущей 3D-сценой без изменения таймлайна или протокола.

Визуальные эффекты: четыре секунды чёрного экрана, плавное открытие подвала,
неподвижные клетки без покачивания, лёгкая атмосферная модуляция,
сдержанный световой акцент и закрывающий fade. Запечённые свечи и лунные лучи
не двигаются. Логотип/Room Code запечены в фоне: скрыты боковой тенью,
без изменения исходной картинки. Клетки рисуются поверх тени.
Лобби-кнопки, код, QR, счётчики и таблички с именами скрываются на время сцены.

Субтитры появляются при фактическом начале Music, сохраняют паузы, плавно
исчезают, поддерживают перенос и контрастную тёмную подложку. Они не зависят от
текста для произношения. Позиции заданы в существующем 1920×1080 FitViewport.

`IntroAudio` принадлежит общему `GameAudio`. Независимые уровни HOST_VOICE,
AMBIENCE, CINEMATIC_SFX, MUSIC заданы в mix конфигурации и умножаются на общие
master/SFX/music. Окружение и музыкальная подложка приглушаются под речь.
Обычные клеточные звуки временно тише, без изменения их событий или исходных файлов.
Громкость вступительного звука цепей дополнительно уменьшена ровно вдвое: gain 0,30 → 0,15.
После skip звук прекращается сразу; асинхронная загрузка завершается и
освобождается на следующих update, чтобы не ждать декодирование в кадре пропуска.

HostVoiceManager использует отдельную секцию `intro` существующего манифеста,
предзагружает только текущий банк реплик и освобождает его при выходе. Повторные
запуски и сетевые refresh не запускают речь заново. При восстановлении возможен
seek в текущую строку. Во время игры нет Qwen/Python/сетевой генерации голоса.

## Голос и пути

Утверждённый эталон — фактический `voice_sample!.wav`, исходник не изменён.
Voice Clone использует существующий Base MLX/Qwen, точный проверенный transcript
и профиль `final_answer_host_ru_v1`. VoiceDesign и чужие голоса не используются.

24 отдельных клипа: `assets/audio/host/ru/intro/<id>_<hash>.ogg`.
Точные файлы и статусы — `assets/audio/host/ru/manifest.json`.
Исходные WAV — `tools/host-tts/output/lossless/intro/` и сохранённые выбранные пробы.
Обработанные WAV — `tools/host-tts/output/intro-treated/`.
`tools/host-tts/output/intro-review.wav` — только файл для прослушивания, не runtime-актив.

Пользователь одобрил немного более грубый тембр: понижение высоты примерно на
0,35 полутона с сохранением темпа, тёплый EQ и мягкая компрессия. Это обработка
того же голоса, а не новый голос или неподдерживаемый emotion-параметр Qwen.
Рецепт — `tools/host-tts/config/intro-treatment.json`. Исходники сохранены.

```sh
# Одна строка / повтор ошибочных строк
/Users/erni/Desktop/QwenTTS/.venv/bin/python tools/host-tts/scripts/narration.py generate --kind intro --id intro_02_01 --force
/Users/erni/Desktop/QwenTTS/.venv/bin/python tools/host-tts/scripts/narration.py retry --kind intro

# Обработка только из lossless-источников, затем новое измерение
python3 tools/host-tts/scripts/postprocess_intro.py
python3 tools/host-tts/scripts/prepare_intro.py

# Утверждение одной прослушанной строки; не автоматическое утверждение пакета
/Users/erni/Desktop/QwenTTS/.venv/bin/python tools/host-tts/scripts/narration.py approve --kind intro --id intro_02_01
```

Новые строки получают review, а не ready. Обычный START GAME не воспроизводит
неутверждённые реплики: показывает возможность пропустить. `introPreview` явно
разрешает review-активы и не меняет их статус. Утверждение всего пакета допустимо
только после явного решения пользователя (`approve --kind intro --all-reviewed`).

## Сеть и пропуск

Desktop посылает START_GAME с `introId`. Сервер использует существующую STARTING
как барьер с IntroGate: вопрос, ответы и таймер ещё не опубликованы. Старые
клиенты без introId сохраняют прежний четырёхсекундный переход для совместимости.
В основном клиенте интро запрашивается всегда.

INTRO_READY/SKIP_INTRO/INTRO_PAUSE/INTRO_RESUME требуют авторизованного host,
gameId и introId. Ранний READY отвергается; повторный финальный сигнал идемпотентен.
Ни одна аудио-длительность не определяет выживание или результат вопроса.
Сервер публикует единственный QUESTION_STARTED, затем действует прежний
PRESENTATION_READY и только после него начинается таймер ответов.

Кнопка **SKIP INTRO »** — справа снизу; клавиши **Space/Esc/Enter** — пропуск,
**P** — пауза/продолжение. На телефонах только ожидание; аудио не передаётся.
Пропуск гасит речь/временные звуки и отменяет будущие cue. Повторная отправка
после потери подтверждения безопасна. При задержке свыше бюджета отправляется
timing warning; сервер не обрывает слова и не открывает вопрос автоматически.

## Проверка

```sh
./gradlew :lwjgl3:introPreview --offline
# R повторяет; после окончания открывается настоящий локальный экран вопроса

./gradlew :core:check :server:test :lwjgl3:compileDevJava --offline
./gradlew :lwjgl3:introNetworkCheck --offline

# Восемь реальных мобильных браузеров, вместе с существующим desktopHostingQA
./gradlew :lwjgl3:desktopHostingQA --offline
node tools/checks/check_intro_browser.cjs
```

Выполнено: чистый таймлайн на 10/30/60/144 FPS; skip в 0/12/58/67 секунд;
пауза, устаревшие callbacks, отсутствие двойных cue, превышение бюджета;
серверные сценарии на 2/8 игроков, host-only, ранний READY, дубли, reconnect;
живой сервер + native экран + 8 WebSocket-контроллеров, полное интро и resize;
8 настоящих браузеров — ожидание без голоса/раннего таймера, reconnect,
запрет player skip и однократное синхронное открытие вопроса. Owned server port
освобождён после теста. Скриншоты — `generated/intro/scene-*.png`.
Последний полный сетевой прогон после выбора третьего дубля: 74,376 секунды;
проверялось нулевое вращение всех клеток в каждом кадре и предел 80 секунд.

## Отсутствующее аудио и ограничения

Работают исходные цепи `sounds/cages/runtime/chain_cage.wav`, тиканье
`sounds/questions/clock_ticks.wav`, окружение `sounds/environment/creepy_basement.mp3`.
Не найдены шаги, отдельный дальний удар, инструмент, щелчок, музыкальный sting
и три одобренных вставки смеха. Точные ожидаемые пути и статус подключения:
[assets/sounds/intro/README.md](../../assets/sounds/intro/README.md).
Ни пустые WAV, ни чужие подстановки, ни произнесённые ремарки смеха не создавались.
Поэтому полный художественный саунд-дизайн пока не закончен.

Самостоятельного управления эмоциями в установленном Base Clone нет. Натуральную
дикцию и актёрскую подачу оценивает человек; техническая валидация этого не доказывает.
Аудио/изображения/референсы/временные файлы остаются вне Git согласно настройкам проекта.
