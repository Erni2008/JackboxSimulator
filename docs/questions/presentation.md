# Постановка вопросов PLAY

## Последовательность

1. Крупный вопрос в центре сцены: отдельные глифы проявляются, чуть смещаются и стабилизируются.
2. QUESTION_VOICE_FINISHED: в тестовом режиме сигнал приходит после полного появления текста.
3. Пауза 2 секунды после этого сигнала.
4. За 0.75 с вопрос поднимается к 74% высоты экрана и уменьшается до 60%.
5. Ответы 1/2/3/4 появляются с шагом 0.18 с, по 0.35 с на проявление.
6. После завершения варианта 4 приходит TIMER_STARTED, запускаются существующие часы на 20 секунд.
7. После закрытия и падения часов неверные ответы исчезают за 0.30 с, правильный растёт до 140% за 0.60 с. Затем результат остаётся на 2.5 с.

Время больше не привязано к старой задержке 3 секунды. Новый сценарий зависит от длины
вопроса и сигнала озвучки. Фон, комнаты и геометрия часов не изменены.

## Где менять параметры

`core/src/main/java/com/erni/finalanswer/gameplay/presentation/QuestionPresentationController.java`:

- CHARACTER_DELAY = 0.035 — шаг появления символов;
- CHARACTER_APPEAR = 0.14 — проявление и успокоение одной буквы;
- STABILIZE_SECONDS = 0.15 — финальная стабилизация;
- VOICE_HOLD_SECONDS = 2 — пауза после окончания озвучки;
- MOVE_SECONDS = 0.75 — движение вверх;
- ANSWER_STAGGER = 0.18, ANSWER_APPEAR = 0.35 — ответы;
- VOICE_TIMEOUT_SECONDS = 60 — защита от потерянного callback озвучки.

`core/src/main/java/com/erni/finalanswer/ui/play/CinematicQuestion.java`:

- FONT_SIZE = 86 — исходный размер шрифта для логической сцены 1600×900;
- MAX_WIDTH_FRACTION = 0.8, MAX_HEIGHT_FRACTION = 0.27 — границы разметки;
- FINAL_SCALE = 0.60 — размер после перемещения;
- prepare() — подгонка длинных вопросов, seed наклонов/смещений по ID вопроса.

`PlayScreen.updatePresentation()` — начальный центр 55% высоты и конечный 74%.
Верхние 12% сцены не заняты вопросом и оставлены для будущих персонажей/ников.

Разметка GlyphLayout и BitmapFontCache рассчитывается один раз на вопрос.
Кернинг, переносы и разбиение длинных слов берутся из LibGDX; при движении
трансформируются сохранённые вершины, а не создаётся новый текст.
Постоянные отклонения букв не меняются во времени. Режим уменьшения движения
убирает индивидуальные наклоны и колебания, сохраняя читаемое проявление.

## Шрифты

Eerie сейчас отсутствует. Английский текст использует существующий Creepster-Regular.ttf,
неподдерживаемые им символы — предзагруженный NotoSans-Regular.ttf.
Оба шрифта создаются один раз и освобождаются вместе с вопросом.
Если добавить Eerie в assets/ui/fonts/Eerie.ttf (или Eerie-Regular.ttf / Eerie.otf),
загрузчик предпочтёт его при следующем запуске. Шрифты извне не скачивались.

## Подключение голоса позже

Контроллер доступен через PlayScreen.presentation(). Перед show() игрового экрана
включи внешний голос: useExternalVoice(true). Подпишись через setListener() или
addListener(). Встроенная подписка запуска часов при этом сохраняется.

При QUESTION_STARTED сохрани event.generation() и передай в аудиоподсистему.
Фактическое начало: onVoiceStarted(generation). Фактическое окончание:
onVoiceFinished(generation). Передавай callbacks на render thread через Gdx.app.postRunnable().
Не вызывай update() отдельно: PlayScreen/RoundController уже продвигают общую шкалу времени.
Не меняй вопрос синхронно внутри обработчика события; ставь переход в postRunnable().

Поколение меняется на каждом новом вопросе: сигнал старой записи игнорируется.
При потере завершения озвучки после 60 с контроллер выдаёт резервный сигнал окончания,
выдерживает паузу и продолжает игру. Внешний голос должен приостанавливаться вместе
с игровым экраном; сама постановка, фон и часы уже используют общий паузируемый шаг.

События: QUESTION_STARTED, QUESTION_VOICE_STARTED, QUESTION_VOICE_FINISHED,
QUESTION_MOVE_STARTED, QUESTION_MOVE_FINISHED, ANSWERS_REVEAL_STARTED,
ANSWERS_REVEAL_FINISHED, TIMER_STARTED. Каждое выдаётся один раз за вопрос.

## Ответы поверх сцены

`ui/play/AnswersPresentationActor.java` владеет четырьмя `AnswerView` и тремя общими
шрифтами. Новых изображений нет. Каждый вариант рисует только номер и текст:
никаких карточек, линий, теневых панелей или рамок. Кернинг и переносы рассчитываются
при смене вопроса, включая слова без пробелов. Размер текста уменьшается до доступной
ширины/высоты. Все кеши используют общие атласы шрифтов.

Настройки (пути относительно `core/src/main/java/com/erni/finalanswer/`):

- `ui/play/AnswersPresentationActor.java`: `PLACEMENT` — центры X/Y в долях экрана
  и фиксированные наклоны; `NUMBER_FONT_SIZE = 112`, `TEXT_FONT_SIZE = 48` для сцены 1600×900.
- `ui/play/AnswerView.java`: `NUMBER_COLOR = "D4D900"`, `TEXT_COLOR = "F2EFE9"`,
  `CORRECT_SCALE = 1.40f`. Поворот и масштаб применяются к номеру и тексту вместе,
  относительно центра видимых глифов. `TEXT_GAP` задаёт промежуток.
- `gameplay/round/RoundTiming.java`: `WRONG_FADE_SECONDS = .30`,
  `CORRECT_GROW_SECONDS = .60`, `STANDARD = new RoundTiming(20, 2.5)`.
  Второй параметр — выдержка ПОСЛЕ полного увеличения, не включая анимацию часов.
- `ui/UiFonts.java`: общий выбор Eerie → Creepster; запасной Noto используется
  только для символов, которых нет в выбранном хоррор-шрифте.

`RoundController.resultElapsedSeconds()` отрицателен, пока часы закрываются и падают.
Его ноль наступает через 0.72 с после таймера: 0.2 закрытие + 0.1 пауза + 0.42 падение.
Текст «правильный ответ» тоже скрыт до этого момента. Неверные варианты становятся
`visible = false` после fade; их цвет не затемняется. Правильный остаётся жёлто-белым.
Общая шкала времени обеспечивает паузу и полный сброс без отложенных callbacks.

Для будущего экрана результатов участников:
`playScreen.setResultsHandler(question -> game.setScreen(...))`.
Обработчик вызывается один раз после выдержки результата, получает исходный Question
и заменяет автоматический переход к следующему вопросу. Вызывать на render thread.
`setResultsHandler(null)` возвращает обычный режим для следующих раундов.

Проверка: дождись конца 20 секунд либо нажми R после появления ответов.
В обоих случаях часы сначала закрываются и падают, затем раскрывается ответ.
`PlayCheck` проверяет задержку, исчезновение, точный масштаб 1.4, все четыре правильных
индекса, длинные строки, паузу, границы, однократный переход и освобождение ресурсов.
