# The Last Command — приборные экраны и защита регулятора

30 октября 2026.

Для LEVER и ADJUSTER созданы отдельные приборные представления на CRT: три положения рычага и шкала угла с указателем и числовым показанием. Состояние берётся из принятого сервером snapshot; это не подсказка о совпадении с ответом. Подтверждение красной кнопкой выделено отдельной полосой. Рядом с физическим регулятором добавлена статичная маркировка R-01 / 45° STEP. Она движется вместе с выдвижным узлом, не вращается с ручкой и не участвует в picking; canvas и материал освобождаются при dispose.

Результат команды показывается отдельным статичным экраном принятия/ошибки. Серверный интервал перехода увеличен с 250 до 700 мс для читаемости; ввод в этот интервал остаётся заблокированным. Правила реакционных задач и их окна нажатия не менялись.

Исправлен дефект инструментальных задач PRESSURE/RADIO/BALANCE: повторный SET уже установленного угла раньше мог менять показание. Теперь такой запрос ничего не меняет. В этих задачах принимается только соседний шаг регулятора ±45°, включая переход 0↔135°; прыжок на 90° отклоняется. Обычный ввод заданного угла ADJUSTER сохраняет свои разрешённые четыре значения.

Проверки: npm browser build, git diff --check; server JUnit — 208 тестов, 0 failures/errors. Новый check_last_command_instruments.cjs проверил реальные HTTP/WS: повтор угла и пропуск позиции не меняют частоту, обычный шаг меняет её на 0,5 МГц без очка; отрисовку рычага, регулятора и принятия; мобильный экран; отсутствие pageerror/shader errors. check_last_command_confirmation.cjs и check_last_command_art_direction.cjs также прошли. Снимки CRT, фронта машины и мобильной сцены осмотрены; файлы в generated/last-command-instruments/.

Основной локальный запуск обновлён на порту 18096; временные серверы этой работы остановлены. Физические телефоны, нагрев и длительная производительность не измерялись.
