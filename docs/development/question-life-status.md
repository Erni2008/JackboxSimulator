# Living players and ghosts during questions

The shared question screen retains up to eight room characters, including ghosts in the trivia `participantIds`. Public server `lifeState` / `isGhost` determines ghost presentation. Both living players and ghosts can answer, play an accepted-answer animation, and receive correctness indicators. Ghosts use their original character with reduced opacity, cool tint, idle animation and a GHOST label. Living characters have an ALIVE label (OFFLINE when disconnected).

Phone question and ghost screens show a public roster with ALIVE / GHOST labels and the local player's YOU marker. It contains no answers, results, or hiding assignments. Ghosts receive the same answer controls, timer and results as living players. Server validation remains authoritative. Cursed Boxes includes ghosts as shooters. Only living players can be assigned to hide and risk elimination.

A trusted server revival changes the next snapshot; the same character object regains living status and eligibility to hide and risk elimination. No automatic revival rule is introduced.

Assets remain local and ignored by Git.

Personal status cards appear above the question and on the result screen. The ghost card explicitly explains continued trivia/scoring participation and immunity from elimination, while still choosing shot targets in Cursed Boxes. Answer receipts precede the room roster. Roster DOM nodes are retained while player identities, names, life states and the local identity are unchanged; unrelated timer/state broadcasts do not rebuild them. Controller QA covers ghost answering, ghost results, return to living presentation and retained roster nodes across refreshes (48 viewport/case combinations).

The question result screen now distinguishes correct, incorrect and timeout results with a decorative inline SVG seal, readable explanatory copy and a separate correct-answer panel. This is presentation only: incorrect answers do not imply elimination. Outcome labels derive from the existing authoritative result fields. The entrance uses only opacity/transform and is disabled by existing reduced-motion/effects settings. No additional media downloads or persistent animation loop. Mobile QA includes all three outcomes, a ghost's correct answer and a long Cyrillic correct answer (51 viewport/case combinations).

Question interaction feedback distinguishes waiting for presentation, ready, sending, server-accepted and closed states. Pending submission never becomes a receipt until the personalized server snapshot confirms a valid answer. The existing clock updates closed feedback immediately at the known deadline even before the next broadcast. Ghosts use identical question controls. Unchanged snapshots retain answer buttons and keyboard focus. The accepted receipt is focusable for accessible handoff when focus is still in the answer group. No added timers, threads, assets or network messages. QA covers delayed confirmation, expiry, invalid indices, accepted answers after expiry and focus preservation (57 viewport/case combinations).

Room presentation adds three join instructions, a connected-player count, occupied-seat progress, a high-contrast identity card and a cached lobby roster. Starting-phase timer refreshes no longer rebuild the guest list. Questions expose completed-question progress through a native accessible progress element. The session footer wraps safely on narrow screens.

The end-of-show screen lists all non-host players by public server score, including ghosts. Equal scores share competition rank; ID is the stable tie-order key. This ranking never decides survival and is empty before GAME_FINISHED. Interrupted shows retain their existing interruption message. No gameplay/server/network changes. Browser QA now covers join, lobby, questions, both mini-games, ghost participation, results, completed/interrupted shows, ties and long names at 320/390/844 px (66 captures); physical-device testing remains manual.

Mode phone polish: Cursed Boxes shows an explicit hide/shoot/spectate briefing. Spectators have no action/selection controls or promised future turn. Box accessibility labels include row/column; keyboard navigation skips unavailable boxes, stays within rows for horizontal movement, and supports Home/End. The Impostor shows only the server-confirmed own clue in its receipt, clears it on reset/suspend, and displays aggregate clue progress only when the server supplies valid counts. No new networking or rules. Browser QA includes spectator restrictions, destroyed-box keyboard navigation, confirmed-versus-draft clues and all earlier cases (69 viewport/case combinations).

Cursed Boxes after trivia now collects private targets from every shooter, including ghosts regardless of trivia correctness. Only wrong-answer living players hide. All targets lock before any shot; duplicates are coalesced into one physical shot in stable roster order. Phones receive only their own selected target and aggregate confirmation counts, with all intact boxes still available while choices are collected. The shared host receives no selected target until lock. Existing shot IDs, host animation acknowledgements, damage, shell/reload audio and reveal paths execute once per unique box. Practice with the original two-shot rules remains a separate developer/standalone flow.
