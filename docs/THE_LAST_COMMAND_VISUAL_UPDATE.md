# THE LAST COMMAND: нативное улучшение визуализации

25 октября 2026. Выполнено отдельно по подтверждению пользователя. Браузерный перенос не начат; план находится в `architecture/browser-3d-plan.md`.

## Изменения

- Перекалиброваны PBR-материалы: сплошная грубая коррозия заменена выборочным износом, различаются окисленный металл, эмаль и стекло. Сохраняются исходные цветовые карты, normal maps и metallic/roughness. Красная большая кнопка и четыре цвета независимы.
- Уменьшено дополнительное процедурное покрытие: корпус 0,50 → 0,22, основание 0,44 → 0,14, cap 0,38 → 0,08. Это параметры слоя, не физические проценты ржавчины. Фактура исходных моделей сохраняется.
- Roughness использует карту поверхности, вместо общего нижнего ограничения 0,79 корпуса. Мелкий рельеф фильтруется по размеру пикселя; дополнительная микрофактура только HIGH.
- Исправлена настройка отражений: у исходных материалов specularColorFactor равен [2,2,2]. Значения ограничиваются единицей только в материалах экземпляров; GLB и общие ресурсы не меняются.
- Вместо оранжевого стандартного indoor IBL используется нейтральное процедурное окружение с холодным заполнением и тёплым металлическим акцентом. Это LDR cubemap, не фотографический HDRI. Карты генерируются один раз при открытии сцены. HIGH: specular cubemap 128², остальные 64². Emission лампы не создаёт новый динамический свет.
- Уменьшены артефакты самозатенения: receiver-plane поправка глубины, bias 0,0025, более тесная область карты теней. PCF остаётся четырёхвыборочным. Включены аналитическое контактное затемнение пола и прежний кэш теней.
- Все параметры света/покрытия доступны в `assets/models/last_command/surface.json`. Существующие LOW/MEDIUM/HIGH и 30/60 FPS, culling и рендер по необходимости сохранены.
- Раскладка, механика, сетевые правила не менялись. Кодовая панель остаётся НАД экраном; основной экран свободен для вопросов.

## Диагностика причин

На одинаковом кадре отключались только normal maps, только новый слой материала и только shadow light. Геометрический узор сохранялся без normal maps, но исчезал без теней: основная причина этого узора — shadow acne. Часть ступенчатых краёв теней всё ещё видна в MEDIUM; это ограничение разрешения карты, не устранённое обещанием «AAA».

Исходный atlas корпуса содержит много запечённого коричневого цвета и неодинаковую плотность детализации. Шейдерная калибровка не восстанавливает отсутствующие данные. Для следующего большого скачка качества понадобятся художественная переработка производных PBR-карт и проверенные маски металла/краски/ржавчины. Оригиналы при этом должны сохраняться. Новые текстуры и модели в этой итерации не создавались.

## Проверка

Команда:

```sh
./gradlew :core:check :shared:check :server:check :lwjgl3:compileJava :lwjgl3:lastCommandPanelCheck :lwjgl3:lastCommandResourceCheck :lwjgl3:lastCommandPreviewCheck :lwjgl3:lastCommandMechanismCheck -Plc.quality=LOW -Plc.shots=/tmp/lc-final-low
```

Exit 0. Server JUnit: 152 теста, 0 failures/errors. Core/shared дополнительно используют существующие verification entry points, поэтому отсутствие JUnit XML там не означает отсутствие проверок.

Нативные проверки: общий mesh/maps кнопок, независимость материалов, press/hold/release, ray targets и окклюзия, dial detents/events, lamp fade/blink, lever UP/MIDDLE/DOWN и pivot, hatch open/close/lock, восемь областей ввода, код вне экрана, camera orbit/pan/reset/collision. HIGH и LOW mechanism checks завершились MECHANISM_CHECK_OK. Снимки осмотрены для фронта, деталей и общего вида; просмотр всех реальных устройств не выполнялся.

GL lifecycle audit после двух циклов загрузки/отрисовки/dispose: 0 оставшихся textures, buffers, framebuffers, renderbuffers, programs, shaders, учитываемых перехватчиком. Это проверка владения GL-объектами в тесте, не доказательство отсутствия любых драйверных утечек.

SHA-256 совпали с optimization.json для 10 оригиналов и 30 runtime GLB. Удвоения тяжёлых текстур нет. В этом этапе модели не оптимизировались заново.

## Измерения производительности

Mac Apple M4, Java 21.0.12.1, OpenGL 2.1, HIGH, backbuffer 1600×900, одинаковые 10 моделей, seed 20261025, hatch right, один круговой путь камеры (период 240 кадров). На прогон 480 кадров прогрева и 1200 кадров сбора, VSync и FPS cap отключены ТОЛЬКО для benchmark; glFinish после render submission учитывает завершение GPU в общем интервале кадра. Это короткий synthetic run, без термометрии и долгого thermal soak.

| Метрика | До, прогон 1 | После, прогон 1 | До, повтор | После, повтор |
|---|---:|---:|---:|---:|
| Средний FPS | 124.730 | 145.551 | 131.433 | 130.074 |
| 1% low FPS | 51.360 | 63.607 | 53.504 | 56.155 |
| Среднее время кадра, мс | 8.017 | 6.870 | 7.608 | 7.688 |
| CPU update, мс | 0.022 | 0.022 | 0.025 | 0.023 |
| CPU render submission, мс | 0.557 | 0.566 | 0.628 | 0.619 |
| Draw calls, среднее | 17.913 | 17.913 | 17.913 | 17.913 |
| Треугольники всех проходов, среднее | 672575.092 | 672575.092 | 672575.092 | 672575.092 |
| Texture bindings, среднее | 30.938 | 29.225 | 29.225 | 29.225 |

Оценка памяти исходных текстур одинакова: 408 MiB; mesh buffers 29,41 MiB, вместе 437,40 MiB. Это расчёт форматов/размеров, НЕ замер VRAM. Он исключает IBL, карты теней, динамические canvas, floor, fonts, driver overhead. HIGH radiance cubemap увеличена с 64² до 128²: дополнительные примерно 384 KiB по формуле RGBA8 с mipmaps; реальное выделение драйвером не измерено. Источников 10, уникальных модельных текстур 30.

GPU time и фактическая GPU/model memory недоступны. Java heap снимки есть в JSON, но они зависят от GC и не равны памяти GLB. Разница первых/повторных texture bindings показывает зависимость счётчика от состояния рендера/подготовки, поэтому число bindings нельзя считать гарантированным выигрышем изменения материалов.

Первый before — реальный замер до правок. Для повторного before использован -Plc.look=legacy в текущем бинарнике; старые shader/light/material settings воспроизведены, общая инфраструктура не откатывалась. Порядок запусков: before, after, after-repeat, before-repeat, без параллельных графических тестов.

Новый вид быстрее в первой паре, но на ~1% медленнее во второй. Доказанного ускорения или снижения нагрева нет. Геометрия/draw calls не выросли; рост IBL мал, но настоящее температурное поведение требует более долгого теста. Эти результаты не переносятся на iPhone/Android.

Воспроизведение:

```sh
./gradlew :lwjgl3:lastCommandBenchmark -Plc.quality=HIGH -Plc.samples=1200 -Plc.warmup=480 -Plc.label=visual-after -Plc.output=/tmp/visual-after.json
./gradlew :lwjgl3:lastCommandBenchmark -Plc.look=legacy -Plc.quality=HIGH -Plc.samples=1200 -Plc.warmup=480 -Plc.label=visual-before -Plc.output=/tmp/visual-before.json
```

Сырые результаты всех четырёх запусков: `generated/last-command-visual/{before,after,before-repeat,after-repeat}.json`. Обычная игра сохраняет лимит профиля и остановку лишних кадров.

## Дополнение: усиленный старый, пошарпанный вид

По следующему запросу пользователя усилен именно износ: нерегулярные сколы эмали до тёмного металла, мелкая направленная абразивная фактура, пятна потёртости и въевшаяся грязь. Покрытие дополнительной ржавчины не увеличено. Relief: body 0,95, base 0,85, cap 1,05; значения согласованы с fallback Java-конфигурацией. Мелкая фактура фильтруется по пиксельному размеру; новые текстуры/GLB не создаются. Изменены weathering.glsl, surface.json, LastCommandSurfaceStyle.java.

Снимок актуального HIGH: `generated/last-command-visual/aged-front.png`. Прежние before/after JSON относятся к предыдущему состоянию шейдера и не являются измерениями этого усиленного износа. Быстродействие этой правки отдельно не заявляется.
