## Один запуск на Mac

Из корня проекта в терминале VS Code:

```sh
./THE_LAST_COMMAND_DEV
```

Нужны Java 21, Node.js/npm, Python 3. При первом запуске npm ci устанавливает закреплённые в web3d/package-lock.json зависимости. Затем скрипт собирает браузерный модуль, запускает watcher и ОДИН Java/Javalin-сервер. Отдельный frontend server не нужен. Браузер по умолчанию открывается автоматически и создаёт DEV-сессию без основного меню/ручного создания комнаты.

- Прямой запуск: http://localhost:8080/last-command-3d/?autostart=1
- Страница подключения и обычных комнат: http://localhost:8080/last-command-3d/
- Проверка сервера: http://localhost:8080/health
- Другой порт: `PORT=8081 ./THE_LAST_COMMAND_DEV`
- Без открытия браузера: `NO_OPEN=1 ./THE_LAST_COMMAND_DEV`

Если порт занят, остановите старый процесс или выберите другой порт. Скрипт не завершает чужие серверы. Ctrl+C в запустившем терминале останавливает Java-сервер и watcher. Если сервер был запущен агентом, перед повторным запуском остановите его текущий процесс.

## Телефон через Wi-Fi

Mac и телефон должны находиться в одной локальной сети без изоляции клиентов. Разрешите входящие подключения Java в macOS firewall, если система запросит их. VPN может давать неподходящий адрес.

Откройте на телефоне адрес из строки «Для телефона» в правой панели игры, например:

```text
http://192.168.1.32:8080/last-command-3d/?room=КОД
```

Укажите уникальное имя и нажмите «Подключиться к DEV». Код уже подставлен из URL. Это полноценный 3D-клиент, не старый телефонный контроллер. Текущий IP Mac можно получить командой `ipconfig getifaddr en0`; при смене Wi-Fi адрес может измениться.

Для отдельной сессии на телефоне нажмите «Подключить машину», затем START. В комнате машина и текущее задание общие; сервер присваивает очко игроку, который отправил верное подтверждение или завершил последовательность. Побеждает первый с 20 очками. Число на CRT — собственный счёт. Камера и качество у каждого клиента собственные.

## Игра — 20 команд

После подключения видна пустая машина. START запускает процедурные задания. Читайте CRT; «К механизму» показывает нужную сторону. Животные и символы расположены сзади. Код вводится стрелками над CRT. Код, карточки, цвет, рычаг и регулятор подтверждаются большой красной кнопкой; люк и цветные кнопки выполняют команду непосредственно. Для уже открытого люка сначала закройте дверцу.

Верный ответ даёт +1. Ошибка не уменьшает счёт и приводит к новому заданию. Запоминание само по себе очка не даёт: число, животное, символ, цвет или четыре вспышки понадобятся через несколько других команд. Для основных задач показываются только необходимые механизмы. Сервер блокирует ранний ввод, скрытые механизмы и повторные подтверждения во время обратной связи.

Время показа запоминания — 4,5 с после развёртывания; вспышка — 600 мс, шаг — 850 мс. Общего таймера поражения и лимита ошибок в основной игре нет. При победе открываются результаты и доступен перезапуск. Seed воспроизводит партию при том же порядке действий; `gameSeed` и `taskSeed` находятся в сетевом состоянии.

## Сохранённые тестовые сценарии

Выберите сценарий перед подключением вместо «Игра — 20 команд». Следующие правила относятся только к диагностике:

1. **Проверка механизмов**: рычаг → регулятор → люк → код из люка + большая кнопка → животное → символ → цвет индикатора → маленькая кнопка → подтверждение большой кнопкой. Сервер генерирует целевые значения из seed. Условия показаны на основном CRT и рядом со сценой. Кодовая панель по-прежнему над CRT.
2. **Световая память**: индикатор и задняя панель показывают четыре сигнала. После показа повторите их четырьмя цветными кнопками: красная №1, зелёная №2, синяя №3, жёлтая №4. Ранние нажатия не засчитываются.

3. **Аварийный протокол / inspection**: восстановите семь состояний в удобном порядке и подтвердите большой кнопкой. Готовность видна в списке.

В световой памяти доступны два серверных повтора сигнала; они не продлевают время раунда. Кнопка «К механизму» помогает найти текущий узел. Звук отключается отдельной кнопкой.

Три неверных ответа или три минуты без решения — поражение. Промежуточные положения при циклическом переключении не штрафуются. Победа/поражение показываются в окне результата. «Новый раунд» сбрасывает механизмы и генерирует следующий воспроизводимый вариант. В DEV перезапуск доступен участникам, в обычной комнате — ведущему.

Seed задаётся перед созданием сессии или URL:

```text
http://localhost:8080/last-command-3d/?autostart=1&seed=42&scenario=memory
```

При сохранённой сессии reload восстанавливает её, а не создаёт новую. Для нового seed сначала нажмите «Сменить комнату». Варианты новых раундов детерминированы начальным seed и номером раунда.

## Управление

- Мышь: движение с ЛКМ — обзор, колесо — зум; короткий клик — действие.
- Телефон: один палец — обзор, касание — действие, два пальца — зум.
- Кнопки: короткое нажатие либо неподвижное удержание после паузы 180 мс. Нажатие анимируется за 0,1 с, отпускание за 0,15 с. Движение больше порога переводит жест в обзор; pinch/cancel/blur отпускают кнопку.
- Рычаг циклически UP/MIDDLE/DOWN; регулятор 0/45/90/135°; стрелки кода изменяют отдельную цифру по кругу; люк открывается и закрывается.
- Индикатор при клике переключает OFF/RED/GREEN/YELLOW/BLUE. Сигнальная анимация сценария временно управляет его визуальным свечением по серверному времени.
- Наведение подсвечивает выбранный механизм. RESET CAMERA возвращает камеру, «Показать заднюю панель» помогает найти животных/символы/сигналы.
- Раздел «Доступное управление» — дополнительный интерфейс тех же серверных действий для доступности и диагностики; picking в 3D работает независимо от него.

Исходных GLB для животных, символов и панели сигналов не найдено. Они реализованы как малые CanvasTexture-поверхности, закреплённые на задней части существующего корпуса. Никакие случайные GLB их не подменяют. Животные и символы рисуются собственными Canvas-силуэтами, без системных эмодзи; подписи CAT/OWL/WOLF/DEER стабильны.

## Полноценный тест существующих комнат

Откройте обычную страницу без autostart в отдельных браузерных контекстах/устройствах. Разверните «Обычная система комнат»:

1. На Mac — «Создать обычную комнату».
2. На двух других устройствах/контекстах — тот же код, разные имена, «Войти гостем».
3. Ведущий нажимает «Запустить в обычной комнате», когда оба гостя онлайн.
4. Ведущий запускает тестовый раунд кнопкой «Новый тестовый раунд».

Сохранены прежние роли: ведущий отдельно от списка 2–8 гостей. DEV допускает быстрый одиночный запуск, но не ослабляет требования обычных комнат. Токен хранится в sessionStorage; не копируйте один токен между вкладками — существующая защита от двойного подключения закроет старый socket.

Старое главное меню и обычный браузерный интерфейс Final Answer остаются по `/`. Development endpoints и GLB allowlist регистрируются только задачей lastCommandDev. Это локальный режим для доверенной Wi-Fi-сети, не конфигурация публичного production-хостинга.

## Качество и производительность

- LOW: 30 FPS, DPR ≤1, без динамических теней, упрощённый слой износа, browser-only mobile GLB (271 тыс. уникальных треугольников вместо прежних 633 тыс.).
- MEDIUM: 60 FPS cap, DPR ≤1,4, без динамических теней; при ручном выборе medium GLB.
- HIGH: 60 FPS cap, DPR ≤2, одна кэшируемая карта теней 1024² (обновляется при движении механизмов), дополнительная микрофактура; high GLB.

Старт всегда с low-ресурсами. Автовыбор делает короткий ограниченный тест render+GPU completion (18 кадров, первые три исключаются); выбирает LOW либо MEDIUM с учётом роста числа пикселей. Автоматический MEDIUM сохраняет low-модели/текстуры ради памяти. HIGH выбирается вручную. Это эвристика, а не обещание FPS. В диагностическом замере gl.finish применяется только при калибровке. При плохом p95 ручной повышенный профиль автоматически понижается до LOW.

Дисплеи на обратной стороне отключаются по нормали поверхности, геометрия использует frustum culling. Неподвижная сцена прекращает лишние GPU-кадры после завершения анимаций; фоновая вкладка не рисуется. Серверная логика и сетевой heartbeat продолжаются. FPS в диагностике — последнее активное окно кадров, а не утверждение, что idle сцена постоянно рисуется с такой частотой.

Панель показывает FPS, средний кадр/p95, draw calls, triangles, модели, геометрии, текстуры, время загрузки и JS heap при доступности. GPU time и фактическая VRAM недоступны. Расчёт памяти исходных буферов/текстур есть в `window.__lc3d.view.metrics.assetMemoryEstimate`: это оценка, исключающая окружение/тени/драйвер.

Измерять нагрузку следует при одинаковом размере окна, качестве и движении камеры: прогреть сцену, вращать 30–60 с, сохранить metrics. Для проверки нагрева и Android/iPhone нужен отдельный 15–20-минутный тест на физических устройствах. Нынешний browser mobile-профиль содержит около 271 тыс. уникальных треугольников. Старый native low содержит 633 тыс.; он не перезаписывался. Работа на слабых Android всё ещё требует физической проверки.

## Разработка и тесты

Браузерный исходник: `web3d/src/games/last-command/`; общие runtime/network/assets/view — `web3d/src/runtime/`. Watcher пересобирает TS/GLSL, Cmd+R загружает изменения и восстанавливает серверную сессию. Java-изменения требуют перезапуска команды. Лог watcher: `/tmp/finalanswer-web3d-watch.log`, серверные ошибки — в терминале, браузерные ошибки — на странице и в DevTools.

```sh
./gradlew :server:test :core:check :shared:check :lwjgl3:compileJava
npm run build --prefix web3d
```

При работающем DEV-сервере:

```sh
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright CHROME_PATH=/path/to/chromium node tools/checks/check_last_command_3d.cjs
```

Скрипт проверяет реальные HTTP/WS, десять GLB, ray picking, отсутствие нажатия при drag, оба тестовых сценария, reset, reconnect, idle rendering и обычную комнату host+2 guests. Результаты по умолчанию `/tmp/last-command-3d-check/`. Мобильный viewport/touch Chromium не равен испытанию Safari/iPhone или настоящего Android.

Откат исходного состояния до браузерной реализации: Git checkpoint `69d86c4`. Бинарные оригиналы не менялись; их контрольные суммы проверяются по optimization.json.


### Восстановление и настройки

Звук и ручное качество сохраняются в браузере. «Подобрать качество» возвращает безопасные mobile-ресурсы перед измерением. Ошибка HIGH/MEDIUM автоматически восстанавливает LOW; если не загружается LOW, используйте «Повторить загрузку». Камера и серверная сессия сохраняются.

В списке целей можно нажать на узел, чтобы камера показала его. Ссылку для телефона можно открыть или скопировать кнопкой рядом. Без доступа к browser storage игра работает, но после reload придётся подключиться заново.

Проверка восстановления при работающем сервере:

```sh
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright CHROME_PATH=/path/to/chromium node tools/checks/check_last_command_resilience.cjs
```


### Подсказки и повтор варианта

В разделе «Как управлять механизмом» показана справка текущего задания или узла под курсором. F переводит камеру к узлу, R сбрасывает её, 1/2 показывают стороны, M переключает звук, ? открывает справку. В полях ввода и окне результата эти клавиши не перехватываются.

Результат содержит зафиксированное сервером время, ошибки и повторы сигнала. «Повторить тот же вариант» запускает те же цели с нуля; «Новый раунд» выдаёт следующий вариант. В обычной комнате эти действия выполняет ведущий. Модели при повторе не загружаются заново.

Подробности и проверки: `docs/THE_LAST_COMMAND_EXPERIENCE.md`.
