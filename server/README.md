# Room server

Запуск из корня проекта (держи этот терминал открытым):

```bash
./gradlew :server:run
```

Игра в другом терминале:

```bash
./gradlew :lwjgl3:run
```

Если сервер уже был запущен до обновления кода, останови его через Ctrl+C и запусти
снова. По умолчанию он слушает порт 8080 на всех сетевых интерфейсах.

Для другого компьютера в той же локальной сети укажи адрес машины с сервером:

```bash
./gradlew :lwjgl3:run -ProomServerUrl=http://192.168.1.10:8080
```

Заменяй пример IP на действительный адрес сервера. На втором клиенте нажми PLAY,
введи код комнаты, своё имя и пароль, если он установлен.

## Сценарий ведущего

CREATE ROOM → название/пароль/лимит/режим → CREATE → GENERATE → OK → главное меню
с кодом, настройками и подключёнными игроками. Ведущий входит в список как Host.
GENERATION CODE без выбранных настроек открывает экран генерации пробного кода.
Пробный код не создаёт комнату и не используется для подключения игроков.

Клиент предлагает код из `RoomCodeGenerator`, сервер атомарно проверяет занятость
и при коллизии назначает свободный. При создании комнаты показывается подтверждённый сервером код.
После создания GENERATE заменяется на OK, повторные запросы кнопкой блокируются.
REROLL справа от кода меняет его через POST `/rooms/{code}/reroll` (поля `token`, `code`).
Только ведущий и только до подключения других игроков: настройки, пароль и токен сохраняются,
старый код становится недействительным. При ошибке интерфейс сохраняет прежний код.
BACK до OK отменяет подготовленную комнату, а не переводит её в активное лобби.

Список обновляется асинхронным heartbeat раз в секунду. LEAVE ROOM удаляет игрока;
выход ведущего закрывает комнату. Пропавшие без выхода клиенты удаляются после
120 секунд без heartbeat при следующем обращении к реестру.
Комнаты хранятся в памяти сервера и не переживают его перезапуск.
Игровые раунды и запуск матча пока не реализованы.

## Протокол

Запросы POST используют `application/x-www-form-urlencoded`, ответы — JSON UTF-8.

| Метод и путь | Поля / результат |
| --- | --- |
| GET `/health` | Статус процесса |
| POST `/rooms` | `name`, `maxPlayers`, `gameMode`, `password`, `code`; комната и приватный токен ведущего |
| POST `/rooms/{code}/join` | `name`, `password`; комната и приватный токен игрока |
| POST `/rooms/{code}/heartbeat` | `token`; актуальная комната и игроки |
| GET `/rooms/{code}` | Публичный снимок без токенов и пароля |
| POST `/rooms/{code}/leave` | `token`; выход или закрытие комнаты ведущим |

Идентификаторы режимов совпадают с `GameMode.getId()` клиента. Лимит 2–8 включает
ведущего. Токены выдаются каждому участнику отдельно. Пароль хранится как salted
PBKDF2-хеш; он не включается в ответы и логи.

`RoomServer` отвечает за HTTP, `rooms/RoomService` — за реестр комнат,
проверку настроек, уникальность кодов, участников, пароль и таймауты.
Клиентский транспорт — `core/.../network/RoomApiClient`, снимок — `rooms/RoomSession`.

Проверка API на запущенном сервере (создаёт и удаляет только собственные тестовые комнаты):

```bash
python3 scripts/check_room_api.py http://127.0.0.1:8080
```

Отдельный проверочный сервер можно запустить командой `./gradlew :server:run --args=18081`.
