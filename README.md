# FinalAnswer

**Начинаешь работать с кодом? Открой [карту проекта](PROJECT_MAP.md).**
Там указано, где находятся экраны, кнопки, игровые режимы, переводы и ресурсы.

A [libGDX](https://libgdx.com/) project generated with [gdx-liftoff](https://github.com/libgdx/gdx-liftoff).

This project was generated with a template including simple application launchers and an `ApplicationAdapter` extension that draws libGDX logo.

## Platforms

- `core`: Main module with the application logic shared by all platforms.
- `lwjgl3`: Primary desktop platform using LWJGL3; was called 'desktop' in older docs.

## Gradle

This project uses [Gradle](https://gradle.org/) to manage dependencies.
The Gradle wrapper was included, so you can run Gradle tasks using `gradlew.bat` or `./gradlew` commands.
Useful Gradle tasks and flags:

- `--continue`: when using this flag, errors will not stop the tasks from running.
- `--daemon`: thanks to this flag, Gradle daemon will be used to run chosen tasks.
- `--offline`: when using this flag, cached dependency archives will be used.
- `--refresh-dependencies`: this flag forces validation of all dependencies. Useful for snapshot versions.
- `build`: builds sources and archives of every project.
- `cleanEclipse`: removes Eclipse project data.
- `cleanIdea`: removes IntelliJ project data.
- `clean`: removes `build` folders, which store compiled classes and built archives.
- `eclipse`: generates Eclipse project data.
- `idea`: generates IntelliJ project data.
- `lwjgl3:jar`: builds application's runnable jar, which can be found at `lwjgl3/build/libs`.
- `lwjgl3:run`: starts the application.
- `test`: runs unit tests (if any).

Note that most tasks that are not specific to a single project can be run with `name:` prefix, where the `name` should be replaced with the ID of a specific project.
For example, `core:clean` removes `build` folder only from the `core` project.

## Developer Inspector

Отдельный инструмент для изучения кода, без запуска игры:

```sh
./gradlew :inspector:run
```

Требуется JDK 21. Инспектор читает Java-исходники `core/src/main/java` и
`lwjgl3/src/main/java`, не создаёт игровые объекты и не вызывает их методы.
Модуль `inspector` не входит в зависимости игры и её распространяемый JAR.

- Слева — дерево пакетов и классов, сверху — поиск по полному имени.
- В центре — диаграмма наследования и реализации интерфейсов.
  Сплошная стрелка ведёт к базовому классу, пунктирная — к интерфейсу.
  Библиотечные типы выделены серым; исходники библиотек не сканируются.
- Выбор класса показывает описание из JavaDoc, объявленные поля,
  сигнатуры методов и конструкторов, родителей, наследников и путь к файлу.
- «Открыть исходник» использует `code --goto` (если VS Code CLI установлен),
  иначе системный редактор. Инспектор не редактирует файлы.
- Масштаб изменяется кнопками; большая схема прокручивается.
- После сохранения исходников инспектор обновляется автоматически. «Обновить» и F5 также доступны. Пересборка игры не нужна.

Это обзор структуры исходников, а не отладчик: он не показывает значения
полей объектов, выполнение методов или все связи вызовов. При ошибках
синтаксиса предупреждение отображается внизу (подробности при наведении).
Внешние типы отображаются по записи в исходнике; неоднозначные имена
не связываются с классами проекта предположительно.

### Визуальная карта содержимого

Главный экран — схема наследования классов, как обзор проекта.
Нажмите класс на схеме или в дереве слева: откроется отдельное окно
«Содержимое класса» с вкладками визуальной карты и сведений / исходника.
В этом окне его карточка показывает объектные поля, данные и
настройки, а стрелки ведут к карточкам типов этих полей. Для классов проекта
карточки показывают краткое содержимое и кнопку «Заглянуть внутрь».
Кнопка «Назад» возвращает к предыдущему классу.

Поля родителей из исходников проекта также показываются с названием класса,
где они объявлены; private-поля принадлежат родительской части объекта, но
не доступны напрямую подклассу. Поля внешних библиотек не разбираются.
Массивы и аргументы коллекций получают связи с типами элементов.
Зелёные стрелки показывают выражения `new` и метод / строку их создания:
это факт из исходника, а не гарантия, что объект существует во время игры.
Начальные выражения полей показываются как код, без вычисления значений.
Методы раскрываются внутри карточки по кнопке.


### Автоматическое обновление

Инспектор проверяет содержимое Java-файлов в модулях `core` и `lwjgl3`
в фоне. После стабильного сохранения (обычно в течение 1–2 секунд)
обновляются схема, дерево и уже открытые сведения о классе. Новые классы,
пакеты и удалённые файлы тоже отслеживаются. Поиск и масштаб сохраняются;
обновление само по себе не открывает окна. При удалении выбранного класса
его окно закрывается. Закрытие главного окна останавливает монитор.

### Компактный просмотр полей и методов

По нажатию на класс открывается вкладка «Поля и методы»: раскрываемые
красные разделы полей и синие разделы методов, включая объявления родителей
из исходников проекта. Поиск фильтрует оба вида объявлений. Стрелка справа
от объектного поля открывает класс его типа, если он есть в проекте.
Значения справа — начальные выражения / места создания из исходника,
не вычисленные значения запущенной игры. Строки доступны только для чтения;
вызова методов и изменения полей здесь нет. Карта связей остаётся
дополнительной вкладкой. Автообновление обновляет и эту таблицу.

## Живые экземпляры (только чтение)

```sh
./gradlew :inspector:runLive
```

Эта команда запускает игру и отдельный процесс инспектора. Нажмите класс
на схеме: снизу появятся достижимые экземпляры этого класса (включая
подклассы). Нажмите карточку экземпляра — откроется таблица текущих
значений полей. Колонка «Где объявлено» отделяет собственные поля от
полей родителей, включая доступные библиотечные поля libGDX.
Двойной щелчок по ссылке или кнопка «Открыть объект выбранного поля»
переходит к связанному объекту. Есть поиск и история переходов.
«Сведения о классе» открывает отдельный обзор исходников.

Снимок создаётся на потоке игры каждые 0,5 секунды и записывается в
отдельный временный файл с ограниченными правами пользователя. Запись и
чтение выполняются в фоне; нет сетевого сервера или команд управления
игрой. Инспектор не вызывает getters, игровые методы или `toString()`
объектов и не меняет значения полей. При закрытии игры живые значения
перестают отображаться; схема исходников остаётся доступной.

Отслеживаются объекты, достижимые от текущей игры через поля, массивы,
libGDX-контейнеры и стандартные Java collections/maps. Это не полный
снимок heap: временные локальные объекты и недостижимые экземпляры не
показаны. Обход ограничен 600 объектами, глубиной 10 и 100 элементами
контейнера; о достижении лимита выводится сообщение. Ссылки на типы
вне поддерживаемого обхода отображаются без перехода. Снимок отражает
состояние после кадра; изменения исходников не заменяют классы уже
работающей JVM — для выполнения нового кода перезапустите runLive.

Обычный `:lwjgl3:run` не включает инспектор. В код игры не добавлены
зависимости, регистрация объектов или обработчики инспектора: наблюдение
подключается отдельным launcher в developer-модуле.
